# Daynote UI 평가와 개선

평가 대상: `src/index.html`, `src/styles.css`, `src/app.js`. 기존 UI를 평가한 점수이며 개선 후 재채점은 하지 않았다.

캘린더와 선택한 날짜의 일정·할 일을 나란히 둔 구조는 실제 업무 흐름에 맞는다. 차분한 색상, Pretendard, 자동 저장 상태, 날짜별 완료 현황은 유지할 가치가 있다. 주요 개선 기회는 작은 글자·낮은 대비와 작은 조작 영역이었다.

## 우선순위와 반영 내용

- **P1 · 가독성**: 입력 본문 12→14px, 설명 11→13px, 오른쪽 진행률 9→12px. 작은 안내 글자를 확대하고 밝은·어두운 테마의 보조 글자와 플레이스홀더 대비를 강화했다. 주말 글자와 주황·노랑 테마의 색상도 읽기 쉽게 조정했다.
- **P2 · 조작 영역**: 체크박스 14→24px, 추가 버튼 25→32px, 삭제 버튼 19×21→28×28px. 기존 SVG 아이콘을 유지하고 입력줄에 더 명확한 포커스 표시를 적용했다.
- **P2 · 키보드 연속성**: 키보드로 삭제하면 이전 입력줄, 마지막 항목 삭제 시 추가 버튼으로 포커스를 옮긴다. 마우스로 삭제할 때 자동으로 입력을 시작하지 않는 기존 규칙을 유지했다. 선택 날짜 제목에는 live announcement를 추가했다.
- **P2 · 작은 창**: 키보드 안내를 줄바꿈하고, 창 높이가 매우 낮을 때 작업 영역을 스크롤할 수 있게 했다. 패널 간격을 정돈하고 상단 장식용 영문 라벨을 제거했다.

기존 9가지 테마, 캘린더/일정/TODO 구성, 내용·완료 항목 순서, 저장·내보내기 기능, Pretendard Medium 및 로고와 월 제목 크기 일치 규칙을 유지했다.

## 검사 근거

독립적인 소스 검토 A 이후 독립적인 자동 검사 B를 수행했다. 개선 전 자동 검사 결과는 36건(대비 20, 작은 UI 글자 10, 작은 본문 5, 아이콘 타일 1)이었다. 이 중 로고 아이콘이 제목 위에 있다는 1건은 실제 가로 배치와 다른 오탐이다. 자동 검사는 모든 항목을 `src/index.html:0`으로 보고했으므로 정확한 위치나 독립 결함 수로 해석하지 않는다.

독립 검토 A는 소스 검토이며, 실제 Electron 화면 확인은 주 에이전트가 별도로 수행했다. 임시 테스트 데이터를 사용해 개선 전후 화면, 920×640 최소 창, 일반 창, 넓은 창, 다크 테마와 설정 화면을 확인했다. 9가지 테마의 대표 텍스트·플레이스홀더 대비를 수치로 확인했다. 전면적인 접근성 인증이나 실제 스크린리더 검증을 뜻하지 않는다.

업무 숙련자에게는 입력과 완료 확인이 빨라지고, 저시력 사용자에게는 본문·보조 정보가 읽기 쉬워지며, 키보드 사용자에게는 삭제 후 위치가 명확해진다. 자동 저장의 안심감과 완료 진행률의 피드백은 유지했다. Tab으로 설명을 전환하는 비표준 동작과 삭제 되돌리기 부재는 기존 제품 규칙으로 남아 있다.

## 후속 조정 (2026-11-08)

위 내용은 최초 평가·개선 당시의 기록이다. 이후 사용자 피드백에 따라 체크박스를 **24px에서 18px로 축소**하고 체크 표시와 설명 글머리표·본문 정렬을 조정했다. 현재 체크박스 크기는 18×18px이며, 위의 14→24px 기록은 중간 개선 단계에 해당한다.

최종 18px 체크박스의 크기·체크·해제 및 밝은·어두운 테마 표시를 Electron에서 확인하고 Windows 설치파일도 다시 빌드했다. 현재 사양은 [요구사항](../../PLAN/requirements.md), 검사 시점·운영체제·최종 로컬 설치파일 체크섬은 [검증결과](../../docs/검증결과.md)를 기준으로 한다.
