# Daynote · 업무 및 일정 캘린더

Daynote는 회사에서 하루의 일정과 할 일을 날짜별로 정리하는 **오프라인 데스크톱 앱**입니다. 출근 후 오늘의 업무를 적고, 업무를 마치면 체크하고, 필요한 기간의 업무 내용을 Excel로 내보낼 수 있습니다.

현재 버전은 **1.2.0**입니다. Windows x64 설치파일을 제공하며, 기록은 사용자의 PC에 저장됩니다. 앱 사용에는 계정, 인터넷 연결, Node.js 설치가 필요하지 않습니다.

**2026-11-08 로컬 빌드 업데이트:** 글자 크기·대비·입력 포커스를 개선하고 체크박스를 18px로 조정했습니다. 변경 사항을 반영한 설치파일은 `dist/Daynote-Setup-1.2.0-x64.exe`입니다. 버전 번호는 그대로이며, 이번에 재생성한 파일은 GitHub Releases에 업로드하지 않았습니다. 아래 배포 링크의 기존 1.2.0 설치파일과 구분하세요.

## 주요 기능

| 기능 | 설명 |
|---|---|
| 월간 캘린더 | 날짜 선택, 이전·다음 달 이동, 오늘로 이동 |
| 일정과 할 일 | 선택한 날짜의 일정(Schedule)과 할 일(TODO List)을 체크박스로 기록 |
| 설명 입력 | 항목 아래에 들여쓰기 설명을 붙이고 긴 내용은 자동 줄바꿈 |
| 완료 현황 | 날짜 칸 아래에 `완료 2/전체 5` 표시, 오른쪽 할 일 카드에 진행률 표시 |
| 자동 저장 | 날짜별 기록을 로컬 파일에 저장하고 앱 재실행 시 복원 |
| Excel 내보내기 | 선택한 기간의 모든 TODO를 날짜·업무 내용·완료 여부로 내보내기 |
| 화면 설정 | 7가지 색상 테마와 밝은·어두운 테마, Pretendard Variable Medium 글꼴 |
| 데스크톱 기능 | 창 크기·위치 복원, Windows 로그인 후 자동 실행 설정 |

완료한 항목은 체크박스만 체크되며 취소선이나 순서 변경은 없습니다. 미완료 업무도 작성한 날짜에 남습니다.

## 설치하고 사용하기

1. 이번 UI 개선본은 로컬의 `dist/Daynote-Setup-1.2.0-x64.exe`를 사용합니다. 기존 공개 배포본은 [설치파일 배포 페이지](https://github.com/chlrudtlr/Codex-Test/releases/latest)의 **Assets**에서 받을 수 있습니다.
2. 설치파일을 실행하고 설치 마법사의 안내에 따라 설치합니다.
3. 시작 메뉴 또는 바탕화면의 **Daynote**를 실행합니다.
4. 왼쪽에서 날짜를 선택하고 오른쪽 입력줄을 클릭해 일정이나 할 일을 적습니다.
5. `Enter` 또는 카드의 `(+)` 버튼으로 항목을 추가하고, 새 항목에서 `Tab`을 눌러 설명을 적습니다.
6. 필요한 기간의 업무를 정리할 때는 상단 **Export**를 사용합니다.

설치 후에는 인터넷 없이 사용할 수 있습니다. Excel 파일을 생성하는 데 Microsoft Excel 설치도 필요하지 않습니다.

업데이트할 때는 실행 중인 Daynote를 종료하고 같은 설치 위치에 새 버전을 설치하세요. 앱 이름과 데이터 저장 위치를 유지하므로 기존 기록을 이어서 사용할 수 있습니다. 데이터 백업 방법은 [사용법](docs/사용법.md#저장-위치와-백업)을 참고하세요.

설치파일은 [GitHub Releases](https://github.com/chlrudtlr/Codex-Test/releases)에서 버전별로 배포하며 소스의 Git 이력에는 포함하지 않습니다. 소스만 받은 경우 아래 개발·빌드 절차로 직접 생성할 수도 있습니다. 현재 설치파일은 코드 서명이 적용되지 않은 개발용 빌드입니다.

## 버전별 설치파일

각 배포 페이지의 **Assets**에서 `.exe` 설치파일과 `SHA256SUMS.txt`를 받을 수 있습니다. 최신 버전은 **1.2.0**입니다.

| 버전 | 주요 변경 | 다운로드 |
|---|---|---|
| 1.2.0 | 기간별 TODO Excel 내보내기 | [설치파일](https://github.com/chlrudtlr/Codex-Test/releases/tag/installer-v1.2.0) |
| 1.1.2 | 삭제 되돌리기 기능 제거 | [설치파일](https://github.com/chlrudtlr/Codex-Test/releases/tag/installer-v1.1.2) |
| 1.1.1 | 입력 동작 개선, Pretendard Medium 동봉 | [설치파일](https://github.com/chlrudtlr/Codex-Test/releases/tag/installer-v1.1.1) |
| 1.1.0 | 화면 정리, 9가지 테마 | [설치파일](https://github.com/chlrudtlr/Codex-Test/releases/tag/installer-v1.1.0) |
| 1.0.0 | 캘린더·일정·TODO 기본 기능 | [설치파일](https://github.com/chlrudtlr/Codex-Test/releases/tag/installer-v1.0.0) |

`installer-v*`는 설치파일 배포용 태그입니다. 1.1.0·1.1.1·1.1.2는 당시 소스를 별도 커밋으로 남기지 않아 설치파일 보관용으로 게시했습니다. 이 중간 버전의 자동 생성 **Source code** 압축파일이 해당 설치파일의 소스 스냅샷을 뜻하지는 않습니다. 자세한 변경·검증 이력은 [검증결과](docs/검증결과.md#버전별-변경-이력)에 있습니다.

다음 버전부터는 소스를 버전별 커밋으로 남긴 뒤, 해당 커밋을 기준으로 `installer-v버전` 릴리스를 만들고 빌드한 `.exe`와 체크섬을 첨부하는 방식으로 이력을 이어갈 수 있습니다.

## Excel로 업무 정리하기

상단의 **Export → 시작일·종료일 선택 → Export → 저장 위치 지정** 순서로 사용합니다.

다음은 출력 형식을 설명하기 위한 예시입니다.

| 날짜 | 업무 내용 | 상태 |
|---|---|---|
| 2026-11-08 | 보고서 검토 | 완료 |
| 2026-11-07 | 회의 자료 준비 | 미완료 |

날짜는 **할 일을 기록한 캘린더 날짜**입니다. 선택한 기간의 완료·미완료 TODO를 모두 포함하며, 연결된 설명은 같은 셀에 줄바꿈으로 표시합니다. 파일 형식은 `.xlsx`이고 최근 날짜부터 나열합니다.

## 개발 환경과 실행

Node.js **22.12.0 이상**과 npm을 준비한 뒤 저장소 루트에서 실행합니다.

```sh
npm ci
npm start
```

의존성 설치와 최초 Electron 실행 파일 다운로드에는 인터넷이 필요합니다. 설치형 앱의 일반 사용자는 이 개발 환경을 준비할 필요가 없습니다.

주요 구성은 Electron 45.2.3, HTML/CSS/JavaScript, ExcelJS 4.4.0입니다. 실제 버전과 명령은 [package.json](package.json)에 정의되어 있습니다.

## 설치파일 빌드

Windows에서 다음 명령으로 Windows x64용 NSIS 설치파일을 생성합니다.

```sh
npm run dist:win
```

현재 출력 파일은 `dist/Daynote-Setup-1.2.0-x64.exe`입니다. 배포 시 필요한 결과물은 이 설치파일이며, `dist/win-unpacked/`와 캐시 폴더 전체를 사용자에게 전달할 필요는 없습니다.

현재 로컬 빌드에는 파일 확인용 `dist/Daynote-Setup-1.2.0-x64.exe.sha256`도 생성되어 있습니다. `npm run dist:win`은 이 별도 체크섬 파일을 자동으로 갱신하지 않으므로 재빌드 후에는 체크섬도 다시 생성해야 합니다. 이번 빌드의 검증 범위와 SHA-256은 [최근 UI 개선 및 설치파일 재생성 기록](docs/검증결과.md#최근-ui-개선-및-설치파일-재생성-2026-11-08)에 있습니다.

| 명령 | 용도 |
|---|---|
| `npm run pack` | 현재 플랫폼의 앱 패키지 생성, 설치파일은 생성하지 않음 |
| `npm run dist:linux` | Linux AppImage 빌드 |
| `npm run dist:mac` | macOS DMG 빌드 |

Linux·macOS 빌드 설정은 준비되어 있지만 1.2.0의 해당 플랫폼 배포·실사용 검증은 완료하지 않았습니다. macOS 빌드는 macOS 환경이 필요하고, 다른 플랫폼에서 Windows용으로 교차 빌드할 때는 추가 도구가 필요할 수 있습니다. Windows 설치파일은 Windows에서 빌드하는 절차를 기준으로 합니다.

## 검사 명령

```sh
npm run check
npm test
npm run test:e2e
```

- `check`: JavaScript 구문 검사.
- `test`: 날짜·진행률·저장·복구·Excel 파일 생성 검사.
- `test:e2e`: 실제 Electron 창을 실행하는 화면·입력·저장·내보내기 검사.

화면 검사에는 그래픽 환경이 필요합니다. 테스트는 별도 임시 데이터 폴더를 사용합니다. 상세 결과와 한계는 [검증결과](docs/검증결과.md)를 참고하세요.

## 프로젝트 구성

```text
Daynote/
├── electron/       # 데스크톱 창, 저장, OS 설정, Excel 파일 생성
├── src/            # 화면, 입력 처리, 테마 스타일, 동봉 글꼴
├── shared/         # 날짜·항목·테마·내보내기 공통 규칙
├── tests/          # 단위 검사와 Electron 화면 검사
├── scripts/        # 구문 검사 및 아이콘 생성 보조 도구
├── PLAN/           # 기획, 요구사항, 참고 이미지
├── docs/           # 사용법과 검증 기록
└── package.json    # 앱 버전, 의존성, 실행·빌드 설정
```

`node_modules/`, `dist/`, `test-results/`, `playwright-report/`, `.tools/`는 Git에서 제외되는 설치·빌드·검증 산출물 또는 임시 도구 폴더입니다.
