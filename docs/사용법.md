# Daynote 사용법

Daynote는 PC 안에 일정과 할 일을 저장하는 데스크톱 캘린더입니다. 설치 후에는 인터넷이나 계정 없이 사용할 수 있습니다.

## 설치와 실행

Windows에서는 `dist/Daynote-Setup-1.0.0-x64.exe`를 실행해 설치합니다. 시작 메뉴 또는 바탕화면의 Daynote로 실행할 수 있습니다. 실행 후 작업표시줄의 아이콘을 우클릭해 **작업표시줄에 고정**을 선택하세요.

앱은 오늘 날짜로 열리고 마지막 창 크기와 위치를 복원합니다. 이전에 사용하던 모니터가 연결되지 않았다면 현재 모니터 안으로 창을 배치합니다.

## 날짜와 기록

- 왼쪽 날짜를 클릭하면 오른쪽에서 그 날짜의 일정과 할 일을 편집합니다.
- 월 제목 옆 화살표로 이전·다음 달을 이동합니다. **오늘** 버튼으로 오늘 날짜로 돌아옵니다.
- 월간 날짜 칸에는 일정 제목을 표시하고, 긴 제목은 `…`으로 생략합니다.
- 일정이 많으면 `+3개`처럼 숨겨진 일정 수를 표시합니다. 날짜를 클릭하면 오른쪽에서 모두 볼 수 있습니다.
- 날짜 칸 아래에는 TODO List의 진행률을 `완료 2/전체 5`처럼 표시합니다. 설명과 비어 있는 항목은 세지 않습니다.
- 일정과 할 일을 완료하면 체크박스만 체크됩니다. 글자 모양이나 항목 순서는 바뀌지 않습니다.
- 끝내지 못한 업무도 작성한 날짜에 남습니다. 다른 날짜로 자동 이동하지 않습니다.

## 입력

일정·할 일 영역의 입력줄을 클릭해 작성합니다. 영역의 빈 곳이나 `+` 버튼을 눌러서도 항목을 추가할 수 있습니다.

| 키 | 동작 |
|---|---|
| Enter | 새 체크박스 항목 추가. 커서 뒤의 글은 새 항목으로 이동 |
| Tab | 새 항목을 바로 위 체크박스의 설명으로 전환 |
| Shift + Tab | 설명을 체크박스 항목으로 전환 |
| 설명에서 Enter | 설명 아래에 새 체크박스 항목 추가 |
| 빈 항목에서 Backspace | 해당 항목 삭제 |

첫 번째 항목은 연결할 상위 항목이 없으므로 설명으로 바꿀 수 없습니다. 내용이 길어지면 자동 줄바꿈됩니다. 설명 역시 줄바꿈되어 보일 수 있지만 하나의 설명 항목입니다. 여러 줄의 텍스트를 붙여넣으면 줄별 체크박스 항목으로 추가됩니다.

항목 오른쪽의 `×`로 삭제할 수 있습니다. 체크박스 항목을 삭제하면 연결된 설명도 함께 삭제됩니다. 아래 알림의 **실행 취소**로 마지막 삭제를 되돌릴 수 있습니다.

## 자동 실행과 저장

오른쪽 위 설정에서 **로그인 후 자동 실행**을 켜거나 끌 수 있습니다. 처음에는 꺼져 있습니다. Windows에서는 설치한 앱에서 이 기능을 사용할 수 있습니다. 개발용 실행과 Linux에서는 자동 실행 스위치가 비활성화됩니다. macOS에서는 설치·서명 상태와 운영체제의 로그인 항목 허용에 따라 동작합니다.

변경한 내용은 자동 저장됩니다. 저장에 실패하면 상단에 오류가 표시되며, 저장 상태를 눌러 다시 시도할 수 있습니다. 마지막 입력은 창을 닫기 직전에도 저장합니다. 정상적인 종료 중 저장에 실패하면 창을 유지하고 오류를 알립니다.

저장 위치는 설정에서 확인할 수 있습니다. Windows의 기본 위치는 `%APPDATA%\Daynote\calendar.json`입니다.

- `calendar.json`: 현재 일정·할 일
- `calendar.json.bak`: 직전 정상 저장본
- `window-state.json`: 창 위치·크기

저장 파일이 손상되면 손상된 원본을 별도 보존하고 정상 백업으로 복원합니다. 백업도 읽을 수 없으면 기존 기록을 덮어쓰지 않고 앱을 종료합니다. 백업 파일은 같은 PC에 있으므로 다른 PC로 옮기려면 앱을 종료한 뒤 이 폴더를 복사하세요.

## 개발 환경에서 실행하기

Node.js 22.12 이상이 필요합니다. 의존성 설치와 최초 Electron 다운로드, 설치파일 빌드에는 인터넷이 필요합니다.

```sh
npm ci
npm start
```

Windows 설치파일 빌드:

```sh
npm run dist:win
```

Windows에서 빌드하면 `dist/`에 NSIS 설치파일이 생성됩니다. 별도의 유료 코드 서명 인증서는 포함되어 있지 않습니다.

Linux에서 Windows 설치파일을 교차 빌드할 때는 NSIS용 Wine 환경이 추가로 필요합니다. Windows에서 빌드하는 방식을 권장합니다.

다른 플랫폼은 해당 운영체제에서 다음 명령으로 빌드할 수 있습니다. Windows 이외의 설치 및 자동 실행은 별도 실기기 검증이 필요합니다.

```sh
npm run dist:linux
npm run dist:mac
```

검증:

```sh
npm run check
npm test
npm run test:e2e
```

화면 검증은 Electron 창을 실행하므로 그래픽 환경이 필요합니다. Linux의 시스템 라이브러리가 없다면 별도 설치가 필요합니다. 테스트는 임시 데이터 폴더를 사용하며 실제 기록을 변경하지 않습니다.
