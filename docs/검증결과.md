# Daynote 검증결과와 변경 이력

**현재 기준: 1.2.0** · **기록 기준일: 2026-11-08**

[서비스 소개 및 검사 명령](../README.md) · [사용법](사용법.md) · [현재 요구사항](../PLAN/requirements.md)

이 문서는 구현 과정에서 수행한 검증을 정리한 기록입니다. 아래 자동화 검사와 배포 패키지 확인은 1.2.0 구현 시 수행했으며, 이번 문서 정리 작업에서 앱 검사를 다시 실행한 결과를 뜻하지 않습니다.

## 1.2.0 검증 요약

| 구분 | 결과 | 범위 |
|---|---|---|
| JavaScript 구문 검사 | 통과 | `npm run check` |
| 모델 단위 검사 | 5개 통과 | 날짜, 진행률, 설명 연결, 데이터 유효성 |
| 저장·창 상태 단위 검사 | 4개 통과 | 저장, 직전 백업, 손상 복구, 창 위치 보정 |
| Excel 단위 검사 | 5개 통과 | 기간·항목 추출, 실제 xlsx 생성·재읽기, 파일 교체 |
| Windows Electron 화면 검사 | 9개 통과 | 기존 조작과 테마, 저장·복원, Export |
| Windows 설치파일 빌드 | 완료 | NSIS x64, `Daynote-Setup-1.2.0-x64.exe` |
| 배포 패키지 대조 | 통과 | 최종 핵심 코드·버전·ExcelJS 동봉 여부 |
| 배포 패키지 Excel 생성 | 통과 | 패키지 내부 모듈과 라이브러리로 xlsx 생성 후 셀 값 재확인 |

단위 검사는 합계 **14개**입니다. 검사 코드와 명령은 다음 절을 참고하세요.

### Windows 화면 검사

[calendar.spec.js](../tests/e2e/calendar.spec.js)에서 다음 9개 시나리오를 확인했습니다.

1. 한국어 텍스트, Enter·Tab 설명 입력, 자동 줄바꿈, 체크 상태, 진행률, 날짜별 보존과 재실행 복원.
2. 9가지 테마 적용, 테마 선택과 업무 기록의 재실행 보존.
3. 긴 일정 말줄임, 숨겨진 일정 개수, 작은 창에서 진행률 표시.
4. 설명↔체크박스 전환, 항목·설명 삭제, 삭제 복원 버튼 미표시, IME 조합 중 Enter 처리.
5. 빈 공간 클릭 시 편집 종료·항목 추가 방지, Enter와 `(+)`를 통한 추가.
6. 동봉 Pretendard 글꼴의 실제 로드·Medium(500) 적용, 월 제목과 로고의 글자 크기 일치.
7. 저장 대기 중 창을 닫아도 마지막 입력 보존, 창 크기 복원 및 재실행 시 크기 오차 누적 방지.
8. Export 버튼 위치, 잘못된 기간·빈 기간 처리, 밝은·어두운 테마와 작은 창의 팝업 배치.
9. 저장 취소·실패 후 재시도, 최신 입력을 포함한 실제 Excel 파일의 세 열·내용·상태 확인.

화면 테스트는 별도의 임시 데이터 폴더를 사용하며 실제 사용자 기록을 변경하지 않습니다. 생성한 Excel은 ExcelJS로 다시 읽어 셀 값과 형식을 확인했습니다.

## 배포 패키지 확인

- Windows에서 설치파일을 생성했습니다.
- `dist/win-unpacked/resources/app.asar`의 핵심 파일이 최종 소스와 일치하는지 확인했습니다.
- 앱 버전이 1.2.0이며 ExcelJS 4.4.0이 런타임 의존성으로 포함되었는지 확인했습니다.
- Windows Electron에서 배포 패키지 내부의 Excel 생성 모듈과 라이브러리를 불러와 실제 `.xlsx` 데이터를 만들고 다시 읽었습니다.

이 확인은 사용자 PC에 설치 마법사를 실행한 실사용 검증과는 구분됩니다. 임시 도구와 `dist/`, `test-results/` 등 산출물은 Git에서 제외되며 소스 저장소만 받은 경우 직접 생성해야 합니다.

## 검증의 한계와 남은 실사용 확인

| 항목 | 현재 확인 범위 |
|---|---|
| 사용자 데모 화면 | 사용자가 제공한 초기·후속 데모 이미지에서 해당 시점 앱 실행 확인. 최신 1.2.0 전체 기능의 수동 검증을 의미하지 않음 |
| 설치·작업표시줄 고정 | 빌드와 설정·사용 절차를 확인. 설치 마법사 및 고정 동작의 별도 수동 검증은 미완료 |
| 로그인 후 자동 실행 | 기능 구현과 설정 조건 확인. 실제 로그아웃·재로그인 검증은 미완료 |
| 한국어 IME | 조합 이벤트 처리를 자동화로 확인. 실제 입력기의 모든 조합 동작을 수동으로 검증하지 않음 |
| 운영체제 저장 창 | 자동화에서 저장 창의 반환값을 대체하고 후속 파일 생성을 검증. 네이티브 저장 창 자체의 수동 조작은 미완료 |
| Excel 프로그램 호환 | xlsx를 생성·재읽기해 내용을 검증. Microsoft Excel 등 각 프로그램에서 직접 여는 수동 검증은 미완료 |
| Linux | 초기 버전의 화면 검사 4개와 창 복원 회귀 검사 수행. 1.2.0 전체 기능·설치 검증은 미완료 |
| macOS | 빌드 설정은 있으나 설치·실행·자동 실행 실기기 검증은 미완료 |

현재 설치파일은 코드 서명 없는 개발용 빌드입니다.

Windows의 소수 배율에서는 Electron의 좌표 반올림으로 복원 크기에 1~2 DIP 차이가 생길 수 있습니다. 앱은 이 차이가 실행할 때마다 저장 크기에 누적되지 않도록 처리하고 검사했습니다. 관련 이슈는 [electron/electron#55245](https://github.com/electron/electron/issues/55245)입니다.

## 재검증 방법

Node.js 22.12.0 이상과 의존성을 준비한 저장소 루트에서 실행합니다.

```sh
npm ci
npm run check
npm test
npm run test:e2e
```

화면 검사에는 그래픽 환경이 필요합니다. 다른 Electron 실행 파일로 검사해야 할 때는 테스트용 환경 변수 `DAYNOTE_ELECTRON_EXECUTABLE`에 해당 실행 파일 경로를 지정할 수 있습니다. 테스트는 `DAYNOTE_TEST_DATA`로 임시 프로필을 사용하며, 설치된 앱의 사용자 데이터 폴더를 검사 대상으로 사용하지 않습니다.

설치파일 재생성은 Windows에서 `npm run dist:win`으로 진행합니다. 기본 개발 환경 및 다른 빌드 명령은 [README](../README.md#설치파일-빌드)에 있습니다.
